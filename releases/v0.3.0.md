# Autopraxis v0.3.0

Adds the signal-first foundation of the self-improving skill lifecycle: Autopraxis can now learn from its own runs and propose adding or retiring skills, always human-gated.

## Highlights

- **Skill-lifecycle signal (M1):** three optional `run-telemetry` `metrics` fields and a read-only `autopraxis telemetry lifecycle` aggregator that refuses to emit add/prune signal below a 5-run floor.
- **Add (M3):** `backprop` turns recurring unmet-need signal into signal-backed proposals for new skills, replacing the hand-curated candidate list.
- **Prune (M4):** governed soft-deprecate via a `deprecated` manifest field, with install-time warnings and validation, split by ownership seam.
- Versioned model-tier catalog (anthropic, openai, moonshot/Kimi).

## Signal fields (`run-telemetry` `metrics`)

- `skills_invoked` / `agents_invoked` — arrays on the `end` event (loader-emitted).
- `run_disposition` — `accepted|edited|rejected` on a late `human_response` event keyed by `run_id` (a downstream fact; never the run's own `end`).
- `unmet_need` (+ `unmet_need_note`) — on the `escalation` event.

```bash
autopraxis telemetry lifecycle [--path <file>] [--min-runs <int>]
```

## Governance

Adding or retiring a skill stays gated by `/council` + human approval; kickoff is manual, no cron. Prune is soft-deprecate only (mark → warn-on-use → remove in a later release). Vendored/persona agents are deprecated upstream in agent-fleet, never marked locally.

## Validation

```bash
npm test
npm pack --dry-run
npm exec -- agent-fleet --version
```

## Known Limitations

- `skills_invoked` is loader-emitted; until a host runtime populates it, usage/prune signal is sparse. Documented, not enforced by Autopraxis.
- The lifecycle loop proposes only; it never autonomously authors or deletes.
